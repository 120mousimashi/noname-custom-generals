## 本轮实机问题与修复目标

旧版本客户端现场已确认两件事：测试场景的身份布局没有通过“主公、忠臣、反贼、内奸各一名”的白名单检查，因此接管没有启用；原面板在游戏画面下沿被裁切，拒绝原因不易看到。这是本轮已取得的实机证据。

V0.1.2 已移除这项身份分布白名单，改为检查本地 normal 身份局的实际四席与单武将；不再要求乱斗场景、主忠反内各一名、固定位置或旧预设玩家配置，也不改写人物身份。新增“全席接管·四人测试”独立预设供预先指定四席武将。面板改挂到页面 body，并放在左侧距顶部 110px 的位置；安装后即显示“全席接管已加载 · 等待四人身份局开局”，关闭、拒绝、运行和暂停分别显示相应状态。

本轮又修正了面板内部元素沿用本体绝对定位后宽度塌缩、文字竖排的样式：面板使用固定宽度和纵向flex布局，标签与按钮改为相对定位。新版安装并重载后，真实客户端左上状态已能横向读取，并从等待变为“全席手动”。

十周年UI会自动选择可响应或可弃置的牌；本版在接管期间临时关闭其 `extension_十周年UI_autoSelect` 偏好，停止时恢复，不保存临时关闭值。最新3项自动回归检查原值恢复、接管期间的设置赋值保留，以及后来替换的属性描述符不被覆盖。真实客户端已确认本次杀、闪响应未被自动预选，需人工点牌、确认；停止后的实机恢复尚未测试。

另外复现了迟加载安装队列与跨 JavaScript 上下文编译两项风险，并作了对应修复。现场没有证实用户实际触发了这两项风险，不能将它们替代已观察到的场景拒绝与面板裁切，或表述为本次实机故障的已确认根因。

## 保留的 14 项原生集成覆盖

| 项目 | 已验证的行为 |
| --- | --- |
| 1. 原生加载与四席 | 旧格式扩展可加载并同步安装；四席为曹操、刘备、孙权、华佗，身份为主、忠、反、内；工具不增加武将；保留原生控制判断且不写 `_trueMe`。 |
| 2. 标准选择 | `chooseBool`、`chooseTarget`、`chooseCard`、`chooseControl` 进入相应角色的原生人工分支，接受明确答复；多次切换不改身份、行动链或座位标记。 |
| 3. 杀闪与决斗 | 闪抵消杀、决斗往复询问实际响应者；实体闪、杀按原生结算消耗，失败响应产生正常伤害，伤害来源保持真实出牌者。 |
| 4. 无懈 | 真实具有无懈能力的席位得到人工窗口；自动拒绝偏好不跳过该窗口；实体无懈消耗且阻止相应锦囊效果。 |
| 5. 两人及多人拼点 | 原生父事件和离线 `chooseCardOL` 保持结果结构，双方或多方各自人工选实体牌；牌进入弃牌堆，点数比较保持原值。 |
| 6. 新观牌移动 | `chooseToMove_new` 走原生人工分支；显式安排满足原过滤条件，每张被查看的实体牌仍被完整计入结果；意外 `processAI` 会使测试失败。 |
| 7. 频繁技与死后选择 | 回合外的测试触发技能经本体频繁技询问流程分别接受拒绝、同意；真实死亡事件之后的合法 `forceDie` 选择仍由该死者人工作答。 |
| 8. 父选择重入与嵌套 | 原生 `chooseToUse` 选择技能按钮、生成 backup、`goto(0)` 重入；中间插入另一席选择后，父事件恢复原角色并完成实体材料付款和用牌。 |
| 9. 濒死救援 | 原生救援流程询问合法救援者；其桃从真实持牌者处消耗，受救者回复体力，原伤害记录与来源保留。 |
| 10. 范围拒绝 | 联机、在线、录像、实际人数非四、副将、非normal身份及场景 `turns`／`washes` 强制胜负条件不能启动；拒绝后没有选择 handler 或人工偏好适配残留。 |
| 11. 停止恢复 | 停止后撤回自身全局 handler、偏好代理和 UI 捕获；已创建事件持有的旧回调不再夺取控制。 |
| 12. 暂停与续跑防护 | 未核验的原生 `choose*` 与狂乱失控在选择内容执行前阻断；设置暂停状态并记录原因；之后新建已知选择也不能绕过已阻断的会话继续运行。 |
| 13. 身份奖惩 | 换席后由真实击杀来源领取击杀反贼的三张牌；主公误杀忠臣时按原生规则弃去自己的实体牌，击杀统计归属不随当前面板改变。 |
| 14. 主公死亡与参考席 | 主公死亡仍在原生身份检查时进入终局入口；最终视角固定为开局参考席，不随最后操作席改变；会话与偏好适配结束。 |

测试的最终答复来自预先明确的人工输入队列，记录每次选择的事件、实际角色及人工分支。测试没有调用 AI 函数来构造人工答案。意外 AI 路径设置了失败哨兵，并以“去掉接管后命中哨兵”的负向对照确认其会失败。

第 7、8 项中的测试技能仅用于构造本体支持的触发、backup 和嵌套流程，没有注册新武将，也不能据此推断所有真实技能均兼容。

## 其他层次的验证与范围限制

控制层的 10 项测试覆盖 20 类原生选择入口、父子恢复、确定性自动结果保留、原生离线多方容器、未知事件阻断、停用撤回和持续阻断守卫。另读取本机 `dclieqiong` 原始自定义 cost，验证其带有 `switchToAuto` 标记时会在内容体执行前暂停；普通委托 `chooseBool` 的 cost 仍能执行并接受明确输入。

人工偏好层的14项测试直接运行摘取的本体原始函数，覆盖频繁技能、预隐藏自动拒绝、无懈偏好、托管按钮及已缓存监听器、W 快捷键、强制计时和恢复；其中最新3项覆盖十周年UI自动选牌偏好的临时关闭、赋值保留与停止恢复。无懈适配仍调用原有过滤函数；清除本工具支持的偏好后，原有 wrapper 若继续拒绝，则以冲突暂停处理。停用不会覆盖后来扩展安装的 wrapper。

会话层的 9 项测试覆盖适用范围检查、生命周期顺序、固定参考席、诊断记录与导出。当前仍明确拒绝身份模式“年机制”，也拒绝场景的 `turns`、`washes` 回合数或洗牌次数强制胜负条件。参考席取接管启动时原本控制的实际角色，不依赖每次决策后的面板席位。

当前版本接管离线、实际四席、单武将的 normal 身份局，包括普通身份局和乱斗身份场景；四席须已完成选将且使用已加载的武将。普通身份局不依赖 `scene`，不因身份不是主忠反内各一名而被拒绝。普通身份的选将仍沿用本体流程；若要自己预先指定四席武将，使用乱斗独立预设并编辑主将。联机、录像、非normal、非四席、副将、年机制与上述场景强制终局限制继续保留。规则要求的唯一确定结果与正常随机性由本体保留；狂乱、强制失控、强制超时代选或其他已识别冲突采用暂停诊断，不通过伪造 `isMine`、`isUnderControl` 或 `_trueMe` 强行接管。

## 有界适配与尚未验收的内容

集成房间的四席初始状态按本体标准武将资料建立。基础用例提供明确的 `scene`、`brawlinfo`、身份和座位；适用范围回归另有删除场景上下文的普通身份用例。它们没有操作真实乱斗场景编辑器，也没有执行完整的客户端选将、洗牌和开局初始化流程。

自动集成房间中的DOM、窗口绘制、动画、手牌容器、最终 `game.check`／`pause`／点击输入和测试回合准备使用有界适配。最终 `game.over` 是记录参数并设置终局状态的测试末端；原生身份判定和死亡流程已运行。另有上述真实客户端点击与牌数变化证据，但真实结算画面、统计写入、录像、死亡后按钮、其他输入方式和多分辨率布局尚未据此验收。

尚未完成 Electron 客户端完整四人多轮及胜负流程，也未对真实安装环境中的任意扩展组合做整体验收。60项自动通过不能替代这些验收。V0.1.2 已完成乱斗预设一整轮四席基础人工操作，以及普通四人身份局的启动、异席实体装备出牌；普通身份整轮与胜负尚未实测，四席全手动选将未实现。看到“导出接管记录”按钮本身不等于已取得控制，接管证据须以实际操作结果为准。

原生或第三方技能可能在普通事件、自定义 UI、异步函数内部直接作决定。对于有明确 `switchToAuto` 等标记的已识别路径，本版采取阻断；对于没有明确标记的私有 AI、私有计时器、缓存回调和未经过受支持选择事件的代码，当前机制无法全面检测。不能据此声称任意技能全兼容，或所有可能的 AI 决策均已覆盖。
